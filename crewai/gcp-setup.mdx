## 📖 Project Overview

### Purpose

This blueprint provides a **complete, enterprise-grade infrastructure** for deploying the CrewAI platform on GCP. Rather than manually configuring dozens of GCP services, you provide a few configuration variables, and Terraform automatically provisions:

- Organizational folder hierarchy
- GCP projects with proper tagging and billing
- GCP APIs and services
- Networking infrastructure (VPC, NAT, firewalls)
- Kubernetes cluster (GKE Standard)
- Database servers (Cloud SQL PostgreSQL with HA and read replicas)
- Storage buckets (with encryption and versioning)
- Secrets management
- IAM roles and service accounts
- Monitoring and logging infrastructure

#### Data Layer
- **Cloud SQL PostgreSQL**:
  - Regional HA (High Availability) across zones
  - PostgreSQL 16 with automatic backups
  - Read replicas for scaling read operations
  - Point-in-time recovery (7 days retention)
  - Private networking (no public IP)
  - SSL/TLS encryption enforced
  
#### Storage
- **GCS Buckets**:
  - Data bucket (versioning, encryption enabled)
  - Logs bucket (lifecycle policies)
  - Automatic backup and retention policies

#### Networking
- **VPC Network**: Custom VPC with multi-zone subnets
- **Cloud NAT**: Secure outbound connectivity for private nodes
- **Firewall Rules**: 
  - Internal communication allowed
  - GKE cluster communication configured
  - SSH access restricted
- **Secondary IP Ranges**: Dedicated ranges for pods and services

#### Security & Secrets
- **Secret Manager**: Secure storage for database credentials
- **IAM Roles**: Fine-grained access control
- **Artifact Registry**: Private Docker image repository
- **SSL/TLS**: Encrypted communication throughout

## 🚀 Quick Start Guide

<Steps>
  <Step title="Clone Repository" icon="git">
    ```bash
    git clone git@bitbucket.org:grupokonecta/crewai-gcp-infra-prod.git
    cd crewai-gcp-infra-prod
    ```
  </Step>
  
  <Step title="Authenticate">
    ```bash
    # Authenticate with GCP
    gcloud auth application-default login
    
    # Configure AWS SSO for Terraform state
    aws sso login --profile default_core_irlanda
    ```
  </Step>
  
  <Step title="Configure Variables">
    ```bash
    cp terraform.auto.tfvars.example terraform.auto.tfvars
    # Edit terraform.auto.tfvars with your values
    ```
  </Step>
  
  <Step title="Validate">
    ```bash
    make validate
    ```
    This runs:
    - `terraform fmt` - Code formatting
    - `terraform validate` - Syntax checking  
    - `tflint` - Best practices linting
  </Step>
  
  <Step title="Initialize & Plan">
    ```bash
    make init
    make plan
    ```
    Preview the 70+ resources that will be created.
  </Step>
  
  <Step title="Deploy Infrastructure" icon="check">
    ```bash
    make apply
    ```
    <Info>
    **Deployment Time:** This takes approximately 15-20 minutes. Grab a coffee!
    </Info>
  </Step>
  
  <Step title="Verify Deployment">
    ```bash
    gcloud container clusters get-credentials crewai-cluster \
      --region <your-region> \
      --project <your-project-id>
    
    kubectl get nodes
    ```
  </Step>
</Steps>

### Essential Variables

All variables are defined in [variables.tf](variables.tf). Key variables you must configure:

#### GCP Organization Structure

```hcl
# Organizational hierarchy configuration (5-level structure)
organization_id        = "123456789"      # GCP Organization ID
root_folder_name       = "Global IT"      # Root folder name
solution_folder_name   = "CrewAI"         # Level 0: Solution/Product folder
env_folder_name        = "PROD"           # Level 1: Environment (DEV, PROD, STG, LGC)
region_folder_name     = "CORP"           # Level 2: Region/Hub (CORP, LATAM, IBERIA)
country_folder_name    = "CO"             # Level 3: Country (CO, BR, AR, etc.)
```

```hcl
# Project metadata
project_id   = "kn-co-globalit-svc-crewai-dev"  # Unique project ID
project_name = "CREWAI-DEV-CO"                  # Display name
description  = "CrewAI Platform Development"
gcp_region   = "us-central1"                     # GCP region
billing_account = "0156A6-7B8C9D-E2F3A4"       # Billing account ID
```

```hcl
# Organizational tagging
department   = "Global IT"
```

#### CrewAI Platform Configuration

```hcl
# Network Configuration
vpc_cidr   = "10.0.0.0/16"     # CIDR block for VPC
zone_count = 3                  # Number of zones (2-3 for HA)

# Storage Configuration
gcs_crewai_data_suffix = "crewai-data"   # Bucket suffix: {project_id}-{suffix}

# Cluster Configuration
cluster_name                = "crewai-cluster"
cluster_initial_node_count  = 1             # Starting number of nodes
cluster_node_machine_type   = "e2-standard-4"  # Machine type for nodes
cluster_authorized_networks = ["203.0.113.25/32"]  # External IPs for kubectl access (auto-detection adds Terraform runner IP)

# Database Configuration
db_instance_name      = "crewai-db"
db_instance_tier      = "db-custom-4-16384"  # 4 vCPU, 16GB RAM
db_edition            = "ENTERPRISE"         # Cloud SQL edition
db_database_name      = "crewai"
db_master_username    = "crewai_admin"
reader_instance_count = 2                    # Read replicas
```

```hcl
# Configure external IP access to GKE cluster API endpoint
cluster_authorized_networks = [
  "203.0.113.25/32",      # Jane's office IP
  "198.51.100.0/24",      # Company VPN subnet
  "192.0.2.50/32"         # CI/CD pipeline IP
]

# Note: The Terraform runner's IP is automatically added during deployment
# Use "gcloud compute networks peerings list" to see VPC peerings
# Use "gcloud container clusters describe" to view authorized networks
```

**How to find your external IP:**

```bash
# Get your current external IP
curl -s https://checkip.amazonaws.com
# Output: 203.0.113.25

# Add to configuration
cluster_authorized_networks = ["203.0.113.25/32"]

# For entire subnet/VPN
cluster_authorized_networks = ["198.51.100.0/24"]
```

**Verify authorized networks after deployment:**

```bash
gcloud container clusters describe crewai-cluster \
  --region <your-region> \
  --project <your-project-id> \
  --format="value(masterAuthorizedNetworks.cidrBlocks[].cidrBlock)"
```

```
│   Your Code  │ ---→  │ Terraform State │ ---→  │  GCP Resources   │
│  (.tf files) │       │   (AWS S3)      │       │  (70+ services)  │
└──────────────┘       └─────────────────┘       └──────────────────┘
       ↑                                                   │
       │                                                   │
       └───────────────── terraform plan/apply ──────────┘
```

## 🐛 Troubleshooting

### Common Issues and Solutions

<AccordionGroup>
  <Accordion title="Terraform Init Fails" icon="alert-circle">
    **Error**: `Error: Failed to download module`
    
    ```bash
    # Clear cache and retry
    rm -rf .terraform
    terraform init
    
    # Check provider configuration
    cat backend.tf
    ```
  </Accordion>
  
  <Accordion title="Authentication Errors" icon="lock">
    **Error**: `Error: Google Cloud credentials not found`
    
    ```bash
    # Re-authenticate with GCP
    gcloud auth application-default login
    gcloud auth list
    
    # For AWS state backend
    aws sso login --profile default_core_irlanda
    ```
  </Accordion>
  
  <Accordion title="API Not Enabled" icon="zap">
    **Error**: `Error: Service [...] has not been used in project`
    
    ```bash
    # APIs auto-enable in modules/apis
    make plan
    make apply
    
    # Or enable manually
    gcloud services enable compute.googleapis.com --project=PROJECT_ID
    ```
  </Accordion>
  
  <Accordion title="Insufficient Quota" icon="alert">
    **Error**: `Error: Quota exceeded for quota metric`
    
    ```bash
    gcloud compute project-info describe --project=PROJECT_ID
    ```
    
    Then request quota increase in GCP Console:
    **IAM & Admin** → **Quotas** → **Select service** → **Request quota increase**
  </Accordion>
  
  <Accordion title="GKE Cluster Timeout" icon="clock">
    **Error**: `Error: timeout while waiting for cluster creation`
    
    ```bash
    gcloud container clusters describe crewai-cluster \
      --region=REGION \
      --project=PROJECT_ID
    
    gcloud container operations list --project=PROJECT_ID
    
    # If stuck, retry
    make destroy
    make apply
    ```
  </Accordion>
  
  <Accordion title="Database Connection Fails" icon="database">
    **Error**: `Error: failed to connect to database`
    
    ```bash
    gcloud sql instances describe crewai-db --project=PROJECT_ID
    gcloud compute firewall-rules list --project=PROJECT_ID
    gcloud services vpc-peerings list \
      --service=servicenetworking.googleapis.com \
      --project=PROJECT_ID
    ```
  </Accordion>
</AccordionGroup>
