# ☁️ CrewAI Platform Installation on Google Cloud

A step-by-step guide to install the CrewAI Platform using Google Cloud Shell, including project setup, configuration, and platform deployment.
For the official installation documentation, see [CrewAI Enterprise Installation Guide](https://enterprise-docs.crewai.com/installation/installation).


<Info>
Google Cloud Shell is a free, browser-based terminal that comes pre-configured with the Google Cloud SDK, kubectl, and other tools you need for installation.
</Info>

<Warning>
**Prerequisites: GCP Infrastructure Setup Required**

Before installing CrewAI Platform, you must first set up your GCP infrastructure including:
- GCP Organization and Project structure
- GKE Kubernetes cluster
- Cloud SQL database
- Cloud Storage buckets
- Networking and security configuration

Follow the [**GCP Infrastructure Setup Guide**](/crewai/gcp-setup) to provision these resources before proceeding with this installation.
</Warning>

## 🚀 Installation Steps

### Step 1: Set Your Project ID

Open Google Cloud Console and launch Cloud Shell, then set your project:

<CodeGroup>
```bash Cloud Shell / Unix
# Set your GCP project ID
export PROJECT_ID="your-gcp-project-id"

# Verify the project is set
gcloud config set project $PROJECT_ID
gcloud config get-value project
```

```powershell Local Windows
# Set your GCP project ID
$PROJECT_ID = "your-gcp-project-id"

# Verify the project is set
gcloud config set project $PROJECT_ID
gcloud config get-value project
```
</CodeGroup>

<Check>
Your Cloud Shell will now use this project for all subsequent commands.
</Check>

### Step 2: Create Project Metadata Folder

Create a folder to organize and store your CrewAI deployment metadata:

<Steps>
  <Step title="Create Metadata Directory">
    ```bash
    # Create a folder to store CrewAI configuration and metadata
    mkdir -p ~/crewai-deployment/$PROJECT_ID/metadata
    
    # Navigate to the directory
    cd ~/crewai-deployment/$PROJECT_ID
    
    # Verify the structure
    ls -la
    ```
  </Step>
  
  <Step title="Create Supporting Directories">
    ```bash
    # Create subdirectories for organization
    mkdir -p metadata/secrets
    mkdir -p metadata/backups
    mkdir -p metadata/logs
    
    # Create a README for documentation
    cat > metadata/README.md << 'EOF'
    # CrewAI Deployment Metadata
    
    Project ID: $PROJECT_ID
    Created: $(date)
    
    ## Directory Structure
    - secrets/: Sensitive configuration files (DO NOT COMMIT)
    - backups/: Backup of configurations and values
    - logs/: Installation and upgrade logs
    
    ## Important Files
    - my-values.yaml: Helm chart values (store in secrets/)
    
    EOF
    
    cat metadata/README.md
    ```
  </Step>
</Steps>

### Step 3: Configure Installation via Enterprise Portal

Access the CrewAI Enterprise Portal to configure and retrieve your installation details:

<Steps>
  <Step title="Access the Install Tab">
    Log in to [https://enterprise.crewai.com/crewai](https://enterprise.crewai.com/crewai) and navigate to the **Install** tab.
  </Step>
  
  <Step title="Configure Instance Details">
    Provide the following information:
    
    **Instance Configuration:**
    - **Instance Name:** FQDN format (e.g., `dev.crewai.konecta.com`)
    - **Kubernetes Distribution:** Google GKE
    - **Cluster Network Availability:** Outbound requests allowed
    
    **Registry Access:**
    - Select: "My workstation can access the internet, the registry AND the cluster"
  </Step>
  
  <Step title="Retrieve Installation Instructions">
    The portal will generate and display your complete Helm Online Install workflow, including:
    - App version selection
    - Authentication credentials and export commands
    - Custom values file template
    - Preflight validation instructions
    - Helm chart installation command with your specific version and values
  </Step>
</Steps>

The portal provides a complete installation sequence with the following steps:

<Steps>
  <Step title="Select a Version">
    Choose your desired app version from the portal's version selector.
  </Step>

  <Step title="Export Credentials and Log In">
    Copy and run the authentication commands provided by the portal:

    ```bash
    export AUTH_TOKEN=<token>
    helm registry login registry.crewai.com --username mischa.vanoijen@konecta.com --password $AUTH_TOKEN
    ```
  </Step>

  <Step title="Create Values Override File">
    Create a `my-values.yaml` file to customize your installation (detailed in Step 4 below).
  </Step>

  <Step title="Install Preflight Plugin">
    Install the preflight validation plugin on GCP Cloud Shell:

    ```bash
    curl https://krew.sh/preflight | bash
    ```
  </Step>

  <Step title="Install the Chart">
    Run the Helm installation command with your specific version:

    ```bash
    helm install crewai-platform oci://registry.crewai.com/crewai/stable/crewai-platform \
      --version 0.3.1 \
      --values my-values.yaml
    ```
  </Step>
</Steps>

<Info>
**Important:** Copy the exact commands provided by the portal, as they contain your unique authentication token and version-specific installation details.
</Info>

### Step 4: Prepare Configuration File (my-values.yaml)

Use the values template provided by the enterprise portal as a starting point. Here's a reference configuration:

<Steps>
  <Step title="Get Portal Template">
    The portal provides a pre-configured `my-values.yaml` template customized for your instance. Download or copy this template as your base configuration.
  </Step>
  
  <Step title="Customize Your Configuration">
    Edit the template with your specific settings:

    <CodeGroup>
    ```bash Cloud Shell / Unix
    # Navigate to your metadata directory
    cd ~/crewai-deployment/$PROJECT_ID/metadata

    # Open in editor (nano or vim)
    nano my-values.yaml
    ```

    ```powershell Windows
    # Navigate to your metadata directory
    cd ~\crewai-deployment\$PROJECT_ID\metadata

    # Open in editor
    notepad my-values.yaml
    ```
    </CodeGroup>

    <Warning>
    **Security: Secrets Management**

    **NEVER commit `my-values.yaml` to version control if it contains secrets!**

    Instead:
    1. Store secrets in Google Cloud Secret Manager
    2. Use CI/CD pipeline to inject secrets
    3. Or create a `.gitignore` entry and manage separately
    </Warning>
  </Step>

  <Step title="Key Configuration Parameters">
    Configure these essential parameters in your `my-values.yaml`:

    ### Application Configuration

    <ParamField path="envVars.APPLICATION_HOST" type="string" required>
      Your domain name (FQDN) for the CrewAI instance

      **Example:** `dev.crewai.konecta.com`
    </ParamField>

    <ParamField path="envVars.AUTH_PROVIDER" type="string" required>
      Authentication provider to use

      **Options:** `workos`, `entra_id`, `google`, `local`
    </ParamField>

    ### Database Configuration

    <ParamField path="envVars.DB_HOST" type="string" required>
      Private IP address of your Cloud SQL PostgreSQL instance

      **Example:** `10.29.0.2`
    </ParamField>

    <ParamField path="envVars.DB_PORT" type="string" default="5432">
      PostgreSQL database port
    </ParamField>

    <ParamField path="envVars.DB_USER" type="string" default="postgres">
      Database username
    </ParamField>

    <ParamField path="secrets.DB_PASSWORD" type="string" required>
      Database password (store in Secret Manager)
    </ParamField>

    ### Storage Configuration (S3-compatible GCS)

    <ParamField path="envVars.STORAGE_SERVICE" type="string" default="amazon">
      Storage service type (use "amazon" for S3-compatible GCS)
    </ParamField>

    <ParamField path="envVars.AWS_REGION" type="string" required>
      GCP region for Cloud Storage buckets

      **Example:** `europe-west1`
    </ParamField>

    <ParamField path="envVars.AWS_BUCKET" type="string" required>
      Main data storage bucket name

      **Example:** `your-project-crewai-data`
    </ParamField>

    <ParamField path="envVars.LOGS_BUCKET" type="string" required>
      Logs storage bucket name

      **Example:** `your-project-crewai-logs`
    </ParamField>

    <ParamField path="envVars.AWS_ENDPOINT" type="string" default="https://storage.googleapis.com">
      S3-compatible endpoint for GCS
    </ParamField>

    <ParamField path="secrets.AWS_ACCESS_KEY_ID" type="string" required>
      GCS HMAC access key ID (from service account)
    </ParamField>

    <ParamField path="secrets.AWS_SECRET_ACCESS_KEY" type="string" required>
      GCS HMAC secret access key
    </ParamField>

    ### WorkOS Authentication

    <ParamField path="envVars.WORKOS_CLIENT_ID" type="string" required>
      WorkOS client ID from your WorkOS dashboard

      **Format:** `client_XXXXXXXXXXXXXXXXXXXXXXXX`
    </ParamField>

    <ParamField path="envVars.WORKOS_AUTHKIT_DOMAIN" type="string" required>
      WorkOS AuthKit domain

      **Example:** `your-domain.authkit.app`
    </ParamField>

    <ParamField path="secrets.WORKOS_API_KEY" type="string" required>
      WorkOS API key (store in Secret Manager)
    </ParamField>

    <ParamField path="secrets.WORKOS_COOKIE_PASSWORD" type="string" required>
      32-character random string for session encryption

      **Generate with:** `openssl rand -hex 16`
    </ParamField>

    ### Container Registry

    <ParamField path="envVars.CREW_IMAGE_REGISTRY_OVERRIDE" type="string">
      Custom container registry for CrewAI images

      **Example:** `europe-west1-docker.pkg.dev/your-project/crewai-enterprise`
    </ParamField>

    <ParamField path="image.registries[].host" type="string" required>
      Container registry hostname

      **Example:** `europe-west1-docker.pkg.dev`
    </ParamField>

    <ParamField path="image.registries[].username" type="string" default="_json_key_base64">
      Registry authentication username (use `_json_key_base64` for GCP)
    </ParamField>

    <ParamField path="image.registries[].password" type="string" required>
      Base64-encoded GCP service account JSON key
    </ParamField>

    ### Web Service

    <ParamField path="web.replicaCount" type="number" default="1">
      Number of web server replicas

      **Development:** `1` | **Production:** `3`
    </ParamField>

    <ParamField path="web.ingress.enabled" type="boolean" default="true">
      Enable ingress controller
    </ParamField>

    <ParamField path="web.ingress.host" type="string" required>
      Ingress hostname (should match APPLICATION_HOST)
    </ParamField>

    ### Worker Service

    <ParamField path="worker.replicaCount" type="number" default="1">
      Number of background worker replicas

      **Development:** `1` | **Production:** `3`
    </ParamField>

    ### OAuth Configuration

    <ParamField path="oauth.enabled" type="boolean" default="false">
      Enable OAuth for third-party integrations
    </ParamField>

    <ParamField path="secrets.OAUTH_DB_HOST" type="string">
      OAuth database host (required if oauth.enabled = true)
    </ParamField>
  </Step>

  <Step title="Reference: Sample Configuration Structure">
    ```yaml
    # CrewAI Platform Helm Values Configuration
    # This example shows both Development and Production settings
    
    postgres:
      enabled: false  # Use external Cloud SQL database
    
    minio:
      enabled: false  # Use external GCP Cloud Storage (S3-compatible)
    
    envVars:
      # Application Configuration
      APPLICATION_HOST: "dev.crewai.konecta.com"  # Your domain name
      
      # Database Configuration
      DB_HOST: "10.29.0.2"  # Private IP of Cloud SQL instance
      DB_PORT: "5432"
      DB_USER: "postgres"
      
      # Container Registry Configuration
      CREW_IMAGE_REGISTRY_OVERRIDE: "europe-west1-docker.pkg.dev/your-project/crewai-enterprise"
      
      # Authentication Provider
      AUTH_PROVIDER: "workos"  # or "entra_id", "google", "local"
      WORKOS_CLIENT_ID: "client_XXXXXXXXXXXXXXXXXXXXXXXX"  # from WorkOS dashboard
      WORKOS_AUTHKIT_DOMAIN: "your-domain.authkit.app"
      
      # Storage Configuration (S3-compatible GCP Cloud Storage)
      STORAGE_SERVICE: "amazon"  # S3-compatible interface
      AWS_REGION: "europe-west1"
      AWS_BUCKET: "your-project-crewai-data"
      LOGS_BUCKET: "your-project-crewai-logs"
      LOGS_REGION: "europe-west1"
      AWS_ENDPOINT: "https://storage.googleapis.com"  # GCS S3-compatible endpoint
      LOGS_ENDPOINT: "https://storage.googleapis.com"
    
    secrets:
      # Database Credentials
      DB_PASSWORD: "[REDACTED]"  # Store in GCP Secret Manager
      
      # GCS HMAC Keys (tied to service account)
      AWS_ACCESS_KEY_ID: "[REDACTED]"  # From Cloud Storage HMAC keys
      AWS_SECRET_ACCESS_KEY: "[REDACTED]"
      
      # Authentication Secrets
      WORKOS_API_KEY: "[REDACTED]"  # from WorkOS API keys
      OAUTH_COOKIE_SECRET: "[REDACTED]"  # Random secure string
      
      # OAuth Configuration
      OAUTH_DB_HOST: "10.29.0.2"
      WORKOS_COOKIE_PASSWORD: "[REDACTED]"
    
    # Container Registry Authentication
    image:
      registries:
        - host: "europe-west1-docker.pkg.dev"
          username: "_json_key_base64"
          password: "[REDACTED]"  # Base64-encoded GCP service account JSON
    
    # Web Service Configuration
    web:
      # DEVELOPMENT: Single replica for cost savings
      replicaCount: 1
      
      # PRODUCTION: Multiple replicas for zero-downtime deployments
      # replicaCount: 3
      # terminationGracePeriodSeconds: 60  # Graceful shutdown time
      
      port: 80
      useHttps: false
      enableSslFromPuma: false
      
      # Ingress Configuration (GCP Load Balancer)
      ingress:
        enabled: true
        className: ""  # Empty for GCP Ingress
        host: "dev.crewai.konecta.com"
        annotations:
          # GCP-specific annotations
          networking.gke.io/managed-certificates: gcp-domains-ssl-cert
          kubernetes.io/ingress.global-static-ip-name: "dev-crewai-konecta-com-external-ip"
          kubernetes.io/ingress.class: "gce"
          networking.gke.io/v1beta1.FrontendConfig: "gcp-sslpolicy"
    
    # Background Job Processing
    worker:
      # DEVELOPMENT: Single worker for cost savings
      replicaCount: 1
      
      # PRODUCTION: Multiple workers for parallel job processing
      # replicaCount: 3
    
    # GCP Configuration
    gcp:
      ssldomains:
        - "dev.crewai.konecta.com"
      sslPolicy: "dev-crewai-ssl-policy"
    
    # OAuth Configuration
    oauth:
      enabled: true
    ```

    <Note>
    **Infrastructure Note**: The static IP address resource must be provisioned in GCP before installation. See the [GCP Infrastructure Setup Guide](/crewai/gcp-setup) for details on creating Compute Address resources, SSL policies, and managed certificates.
    </Note>
  </Step>
</Steps>

### Key Configuration Differences: Development vs Production

<Tabs>
  <Tab title="Development">
    ```yaml
    # Development Configuration (Cost-optimized)
    
    web:
      replicaCount: 1  # Single instance to save costs
    
    worker:
      replicaCount: 1  # Single worker for background jobs
    
    # DNS: dev.crewai.konecta.com
    # Resources: Minimal (adequate for testing/validation)
    # Scaling: Manual - adjust replicaCount as needed
    ```

    <Tip>
    Development environments typically use:
    - Single replicas for all services
    - Smaller machine types (e2-small, e2-medium)
    - Reduced resource limits
    - Shared infrastructure when possible
    </Tip>
  </Tab>

  <Tab title="Production">
    ```yaml
    # Production Configuration (High Availability)
    
    web:
      replicaCount: 3  # Three replicas for zero-downtime deployments
      terminationGracePeriodSeconds: 60  # Allow graceful shutdown
    
    worker:
      replicaCount: 3  # Distribute background job processing across replicas
    
    # Auto-scaling (if enabled):
    # minReplicas: 3
    # maxReplicas: 10
    # targetCPUUtilizationPercentage: 70
    
    # DNS: crewai.konecta.com (or prod domain)
    # Resources: Production-grade (CPU/Memory allocations)
    # Scaling: Auto-scaling enabled
    ```

    <Tip>
    Production environments should use:
    - Multiple replicas (minimum 3 for high availability)
    - Larger machine types (e2-standard or higher)
    - Resource requests and limits properly configured
    - Horizontal Pod Autoscaling (HPA) enabled
    - Separate infrastructure from development
    </Tip>
  </Tab>
</Tabs>

### Sensitive Fields Security

<Warning>
**Never Store Secrets in my-values.yaml**

The following fields must **NEVER** be committed to version control:

- `DB_PASSWORD`: Store in Google Cloud Secret Manager
- `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`: GCS HMAC credentials
- `WORKOS_API_KEY`: WorkOS authentication token
- `OAUTH_COOKIE_SECRET`: Cryptographic key for session management
- `WORKOS_COOKIE_PASSWORD`: Password for WorkOS integration
- `image.registries[].password`: Container registry credentials

**Recommended approach:**
1. Store secrets in Google Cloud Secret Manager
2. Use Kubernetes External Secrets Operator (ESO) to sync them
3. Reference Secret Manager values in your deployment pipeline
4. Or use GCP Workload Identity for automatic credential injection
</Warning>

### Step 5: Prepare Your Environment

Ensure your cluster is ready for deployment:

<Steps>
  <Step title="Verify Cloud SQL Connection">
    If using Google Cloud SQL, retrieve your connection details:
    
    ```bash
    # List your Cloud SQL instances
    gcloud sql instances list

    # Get specific instance details
    gcloud sql instances describe crewai-db \
      --format="get(connectionName,ipAddresses[0].ipAddress)"

    # For Private IP (recommended for Cloud SQL)
    gcloud sql instances describe crewai-db \
      --format="get(ipAddresses[0].ipAddress)"
    ```
    
    <Info>
    **Connection String Format**

    For Cloud SQL Private IP:
    ```
    DB_HOST: your-instance.c.your-project.internal
    ```
    </Info>
  </Step>

  <Step title="Verify Default Storage Class">
    Ensure your cluster has a default storage class:
    
    ```bash
    # Check current storage classes
    kubectl get storageclass

    # Set standard as default (if not already)
    kubectl patch storageclass standard \
      -p '{"metadata": {"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
    ```
    
    <Check>
    **Storage Class Ready**

    Your cluster now has a default storage class for persistent volumes.
    </Check>
  </Step>

  <Step title="Install Preflight Validation Plugin">
    Install the preflight plugin from the portal command:
    
    ```bash
    # From portal step 4: Install preflight plugin
    curl https://krew.sh/preflight | bash
    
    # Add Krew to PATH
    export PATH="${KREW_ROOT:-$HOME/.krew}/bin:$PATH"
    
    # Verify installation
    kubectl preflight --version
    ```
  </Step>
</Steps>

### Step 6: Run Preflight Validation

Validate your cluster meets all CrewAI requirements before installation:

```bash
# Run preflight checks with your values file
helm template oci://registry.crewai.com/crewai/stable/crewai-platform \
  --values my-values.yaml \
  | kubectl preflight -

# View detailed results
echo "Preflight check complete. Review any warnings or errors above."
```

<Warning>
**Address Preflight Issues**

The preflight check validates:
- ✓ Cluster resources (CPU, memory)
- ✓ Storage classes
- ✓ RBAC permissions
- ✓ Kubernetes version compatibility

Address any failures before proceeding to installation.
</Warning>

### Step 8: Upgrade the Platform

To upgrade to a newer version of CrewAI Platform:

<Steps>
  <Step title="Prepare for Upgrade">
    <CodeGroup>
    ```bash Cloud Shell / Unix
    # Navigate to your metadata directory
    cd ~/crewai-deployment/$PROJECT_ID/metadata

    # Backup your current values file
    cp my-values.yaml my-values.yaml.backup.$(date +%Y%m%d-%H%M%S)

    # Check available chart versions
    helm search repo registry.crewai.com/crewai/stable --versions
    ```

    ```powershell Windows
    # Navigate to your metadata directory
    cd ~\crewai-deployment\$PROJECT_ID\metadata

    # Backup your current values file
    Copy-Item my-values.yaml "my-values.yaml.backup.$(Get-Date -Format 'yyyyMMdd-HHmmss')"

    # Check available chart versions
    helm search repo registry.crewai.com/crewai/stable --versions
    ```
    </CodeGroup>
  </Step>

  <Step title="Review Changes">
    ```bash
    # Preview what will change
    helm upgrade crewai-platform \
      oci://registry.crewai.com/crewai/stable/crewai-platform \
      --values my-values.yaml \
      --dry-run --debug
    ```

    <Tip>
    Review the output carefully to understand what resources will be modified during the upgrade.
    </Tip>
  </Step>
  
  <Step title="Execute Upgrade">
    ```bash
    # Perform the upgrade
    helm upgrade crewai-platform \
      oci://registry.crewai.com/crewai/stable/crewai-platform \
      --values my-values.yaml
    
    # Monitor the rollout
    kubectl rollout status deployment/crewai-platform-web
    
    # Verify upgrade success
    kubectl get pods
    ```
  </Step>
</Steps>

## 🐛 Troubleshooting

### Common Issues and Solutions

<AccordionGroup>
  <Accordion title="Pods Not Starting" icon="alert-circle">
    ```bash
    # Check pod status and events
    kubectl describe pod <POD_NAME>
    
    # View pod logs for errors
    kubectl logs <POD_NAME>
    
    # Check for image pull errors
    kubectl get events --sort-by='.lastTimestamp'
    ```
    
    **Common Causes:**
    - Registry authentication failed → Re-check credentials
    - Insufficient cluster resources → Scale cluster
    - Missing default storage class → Run Step 7 again
  </Accordion>
  
  <Accordion title="Registry Authentication Failed" icon="lock">
    ```bash
    # Re-authenticate with the registry
    helm registry login registry.crewai.com \
      --username $CREWAI_EMAIL \
      --password $CREWAI_TOKEN \
      --insecure
    
    # Clear cache and retry
    rm -rf ~/.config/helm/registry/config.json
    helm registry login registry.crewai.com \
      --username $CREWAI_EMAIL \
      --password $CREWAI_TOKEN
    ```
  </Accordion>
  
  <Accordion title="Database Connection Errors">
    ```bash
    # Test Cloud SQL connectivity from pod
    kubectl exec -it <POD_NAME> -- psql \
      -h $DB_HOST \
      -U $DB_USER \
      -d $POSTGRES_DB

    # Check firewall rules
    gcloud compute firewall-rules list --filter="name~'gke'"

    # For Cloud SQL, verify Private IP connectivity
    gcloud sql instances describe crewai-db --format='get(ipAddresses)'
    ```

    **Common Issues:**
    - Private IP not enabled on Cloud SQL instance
    - VPC peering not configured correctly
    - Firewall rules blocking GKE to Cloud SQL traffic
  </Accordion>
  
  <Accordion title="Storage Issues">
    ```bash
    # Check persistent volumes
    kubectl get pv
    kubectl get pvc

    # Describe problematic PVC
    kubectl describe pvc <PVC_NAME>

    # Check storage class
    kubectl get storageclass standard
    ```

    <Tip>
    Ensure your GKE cluster has the appropriate IAM permissions to create persistent disks in your project.
    </Tip>
  </Accordion>

## 📝 Installation Log and Backup

Keep records of your installation:

<CodeGroup>
```bash Cloud Shell / Unix
# Save installation timestamp
echo "Installation Date: $(date)" >> metadata/installation.log

# Backup your configuration
cd ~/crewai-deployment/$PROJECT_ID
tar -czf metadata/backups/crewai-config-$(date +%Y%m%d-%H%M%S).tar.gz metadata/

# Export cluster information
kubectl cluster-info dump --output-directory=metadata/logs/cluster-dump-$(date +%Y%m%d)

# Save Helm release information
helm list --all-namespaces > metadata/logs/helm-releases.txt
kubectl describe nodes > metadata/logs/nodes-info.txt
```

```powershell Windows
# Save installation timestamp
"Installation Date: $(Get-Date)" | Out-File -Append metadata\installation.log

# Backup your configuration
cd ~\crewai-deployment\$PROJECT_ID
Compress-Archive -Path metadata\* -DestinationPath "metadata\backups\crewai-config-$(Get-Date -Format 'yyyyMMdd-HHmmss').zip"

# Save Helm release information
helm list --all-namespaces | Out-File metadata\logs\helm-releases.txt
kubectl describe nodes | Out-File metadata\logs\nodes-info.txt
```
</CodeGroup>

<Note>
Regularly backup your configuration files and keep a history of changes for rollback purposes.
</Note>
