# Development Environment Setup

This guide walks you through setting up your local development environment for working with the Google Cloud infrastructure codebase.

<Tip>
Complete the [Prerequisites](/developer-guide/prerequisites) before starting this setup guide.
</Tip>

## Step 1: Clone the Repository

<CodeGroup>
```bash Unix/Linux
# Clone the repository
git clone https://github.com/your-org/gcp-iac-repo.git
cd gcp-iac-repo

# Verify the structure
ls -la
```

```powershell Windows
# Clone the repository
git clone https://github.com/your-org/gcp-iac-repo.git
cd gcp-iac-repo

# Verify the structure
dir
```
</CodeGroup>

## Step 2: Install Dependencies

Ensure you have all required tools installed (see [Prerequisites](/developer-guide/prerequisites)):

<CodeGroup>
```bash Unix/Linux
# Verify Terraform
terraform version

# Verify gcloud
gcloud version

# Verify Git
git --version
```

```powershell Windows
# Verify Terraform
terraform version

# Verify gcloud
gcloud version

# Verify Git
git --version
```
</CodeGroup>

<Check>
All commands should return version numbers without errors.
</Check>

## Step 3: Configure Google Cloud Authentication

<Tabs>
  <Tab title="User Credentials (Development)">
    Use this method for local development with your user account:

    ```bash
    # Login with your user account
    gcloud auth login

    # Set application default credentials
    gcloud auth application-default login

    # Set your project
    gcloud config set project YOUR_PROJECT_ID
    ```

    <Note>
    User credentials are convenient for development but should never be used in CI/CD pipelines.
    </Note>
  </Tab>

  <Tab title="Service Account (CI/CD)">
    Use this method for automated deployments and CI/CD:

    ```bash
    # Create a service account key (if needed)
    gcloud iam service-accounts keys create key.json \
      --iam-account terraform@PROJECT_ID.iam.gserviceaccount.com

    # Set the environment variable
    export GOOGLE_APPLICATION_CREDENTIALS="$(pwd)/key.json"
    ```

    <Warning>
    **Security Best Practice**: Never commit service account keys to version control. Add `*.json` to your `.gitignore`.
    </Warning>
  </Tab>
</Tabs>

## Step 4: Enable Required APIs

Enable the necessary Google Cloud APIs:

<CodeGroup>
```bash Using Script
# Navigate to the scripts directory
cd scripts

# Run the API enablement script (if available)
./enable-apis.sh
```

```bash Manual
# Enable APIs manually
gcloud services enable \
  compute.googleapis.com \
  storage.googleapis.com \
  iam.googleapis.com \
  cloudresourcemanager.googleapis.com \
  servicenetworking.googleapis.com \
  secretmanager.googleapis.com \
  logging.googleapis.com \
  monitoring.googleapis.com
```
</CodeGroup>

<Info>
API enablement can take a few minutes. You can check the status in the [GCP Console](https://console.cloud.google.com/apis/library).
</Info>

## Step 5: Set Up Terraform Backend

The Terraform backend stores state in Google Cloud Storage.

### Create Backend Bucket

<CodeGroup>
```bash Unix/Linux
# Set variables
PROJECT_ID="your-project-id"
BUCKET_NAME="terraform-state-${PROJECT_ID}"

# Create the bucket
gsutil mb -p ${PROJECT_ID} -l us-central1 gs://${BUCKET_NAME}

# Enable versioning
gsutil versioning set on gs://${BUCKET_NAME}

# Apply lifecycle policy
gsutil lifecycle set lifecycle.json gs://${BUCKET_NAME}
```

```powershell Windows
# Set variables
$PROJECT_ID = "your-project-id"
$BUCKET_NAME = "terraform-state-$PROJECT_ID"

# Create the bucket
gsutil mb -p $PROJECT_ID -l us-central1 gs://$BUCKET_NAME

# Enable versioning
gsutil versioning set on gs://$BUCKET_NAME

# Apply lifecycle policy
gsutil lifecycle set lifecycle.json gs://$BUCKET_NAME
```
</CodeGroup>

Create `lifecycle.json`:

```json
{
  "lifecycle": {
    "rule": [
      {
        "action": {"type": "Delete"},
        "condition": {
          "numNewerVersions": 10
        }
      }
    ]
  }
}
```

<Note>
This lifecycle policy keeps the 10 most recent versions of each state file and deletes older versions to save storage costs.
</Note>

### Configure Backend

Update `backend.tf` or create environment-specific backend:

```hcl
terraform {
  backend "gcs" {
    bucket = "terraform-state-your-project-id"
    prefix = "agentic-ai-infrastructure/dev"
  }
}
```

## Step 6: Configure Terraform Variables

### Copy Example Variables

<CodeGroup>
```bash Unix/Linux
# Copy the example file
cp terraform.tfvars.example terraform.tfvars

# Or for environment-specific
cp environments/dev/terraform.tfvars.example environments/dev/terraform.tfvars
```

```powershell Windows
# Copy the example file
Copy-Item terraform.tfvars.example terraform.tfvars

# Or for environment-specific
Copy-Item environments/dev/terraform.tfvars.example environments/dev/terraform.tfvars
```
</CodeGroup>

### Edit Variables

Edit `terraform.tfvars` with your values. Here are the key parameters:

<ParamField path="project_id" type="string" required>
  Your Google Cloud project ID
</ParamField>

<ParamField path="region" type="string" default="us-central1">
  GCP region for resource deployment
</ParamField>

<ParamField path="zone" type="string" default="us-central1-a">
  GCP zone within the region
</ParamField>

<ParamField path="environment" type="string" required>
  Environment name (dev, staging, prod)
</ParamField>

<ParamField path="vpc_name" type="string" default="agentic-ai-vpc">
  Name of the VPC network
</ParamField>

<ParamField path="subnet_name" type="string" default="agentic-ai-subnet">
  Name of the subnet
</ParamField>

<ParamField path="instance_type" type="string" default="e2-small">
  GCE machine type for compute instances
</ParamField>

<ParamField path="min_instances" type="number" default="1">
  Minimum number of instances for autoscaling
</ParamField>

<ParamField path="max_instances" type="number" default="3">
  Maximum number of instances for autoscaling
</ParamField>

**Example `terraform.tfvars`:**

```hcl
project_id  = "your-project-id"
region      = "us-central1"
zone        = "us-central1-a"
environment = "dev"

# Network configuration
vpc_name    = "agentic-ai-vpc"
subnet_name = "agentic-ai-subnet"

# Compute configuration
instance_type = "e2-small"
min_instances = 1
max_instances = 3
```

## Step 7: Initialize Terraform

```bash
# Navigate to terraform directory
cd terraform

# Initialize Terraform
terraform init

# Verify initialization
terraform version
```

Expected output:

```
Initializing the backend...
Initializing provider plugins...
- Finding hashicorp/google versions matching "~> 5.0"...
- Installing hashicorp/google v5.0.0...
Terraform has been successfully initialized!
```

## Step 8: Validate Configuration

```bash
# Validate syntax
terraform validate

# Format code
terraform fmt -recursive

# Check for issues
terraform plan
```

<Tip>
Run `terraform fmt` before committing code to ensure consistent formatting across the team.
</Tip>

## Step 10: Configure Your IDE

### VS Code

Install extensions:

```bash
# Install HashiCorp Terraform extension
code --install-extension hashicorp.terraform

# Install Google Cloud Code extension
code --install-extension GoogleCloudTools.cloudcode
```

Configure settings in `.vscode/settings.json`:

```json
{
  "terraform.format.enable": true,
  "terraform.languageServer.enable": true,
  "files.associations": {
    "*.tf": "terraform",
    "*.tfvars": "terraform"
  }
}
```

### IntelliJ IDEA

1. Install the HashiCorp Terraform plugin
2. Configure Terraform executable path
3. Enable auto-formatting on save

If `terraform plan` completes without errors, your setup is successful!

## Troubleshooting

<AccordionGroup>
  <Accordion title="Backend Initialization Fails">
    ```bash
    # Verify bucket exists
    gsutil ls gs://terraform-state-bucket

    # Check permissions
    gcloud projects get-iam-policy PROJECT_ID

    # Try re-initializing
    terraform init -reconfigure
    ```

    **Common Causes:**
    - Bucket doesn't exist - create it first
    - Insufficient permissions - ensure you have Storage Admin role
    - Incorrect bucket name in backend.tf
  </Accordion>

  <Accordion title="Authentication Errors">
    ```bash
    # Re-authenticate
    gcloud auth application-default login

    # Verify credentials
    gcloud auth list

    # Check service account (if using)
    gcloud iam service-accounts list
    ```

    **Common Causes:**
    - Expired credentials - re-authenticate
    - Wrong project set - verify with `gcloud config get-value project`
    - Service account key file path incorrect
  </Accordion>

  <Accordion title="Provider Version Issues">
    ```bash
    # Update provider versions in versions.tf
    # Then re-initialize
    terraform init -upgrade
    ```

    **Common Causes:**
    - Outdated provider version in lock file
    - Incompatible provider version constraints
    - Cached provider plugins
  </Accordion>

  <Accordion title="State Lock Issues">
    If state is locked (another operation in progress):

    ```bash
    # Check for locks
    terraform force-unlock LOCK_ID

    # Only use if you're sure no other operation is running
    ```

    <Warning>
    Only force-unlock if you're certain no other Terraform operation is running. Doing so during an active operation can corrupt your state.
    </Warning>
  </Accordion>
</AccordionGroup>
